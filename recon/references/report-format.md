# Report format contract

Every skill in this set writes markdown reports. The rules are not stylistic:
the user reads these on a narrow screen and wants prose and bullets, never
tables.

## Hard rules

1. No markdown tables. Not for scores, not for counts, not for summaries.
   `report-lint.sh` fails on any `|` outside a fenced code block.
2. One root report per scope entry links every part below it.
3. Split before a part gets large: at most 250 hosts and roughly 300 KB.
4. Every part is linked from its index; `report-lint.sh` checks this.
5. Facts, then interpretation. A status code or title is evidence; a
   vulnerability claim needs a reproduction.

## Instead of a table

Use a bullet with an em-dash value:

```markdown
- `admin.example.com` — tier 1 · status 403 · nginx/1.21.0 · CDN cloudflare
  - signals: status-403, admin, no-registration
  - next: header and path bypass attempts, then auth review
```

Use a definition-style bullet list for per-host detail:

```markdown
- **Status** — 403, body 512 bytes
- **Title** — Forbidden
- **Server** — nginx/1.21.0
- **CDN** — none detected
- **Why it matters** — the route exists but the app refuses anonymous access
```

Use short subsections when a bullet would run long:

```markdown
### admin.example.com

The host answers 403 on `/` and 200 on `/login`. The login form posts to
`/api/session` and sets an HttpOnly cookie.
```

## Where the priority report lives

The priority report is the one file a human opens first, so it sits at the
target root, not inside the artifact tree:

- `targets/<target>/PRIORITY.md`
- `targets/<target>/priority/` — tier files, only when the report is split

Everything else under `artifacts/recon/` is supporting material (raw httpx,
browser observations, per-host reports).

## Single vs split

- Small scope (hosts ≤ `--split-threshold`, default 250): one file,
  `PRIORITY.md`, with a section per tier. Every host appears exactly once.
- Large scope (over the threshold): `PRIORITY.md` becomes an index — counts,
  top picks, notes and links — and each tier gets its own file:
  `priority/tier0.md`, `tier1.md`, … A tier larger than 250 hosts is chunked
  further: `tier1_001.md`, `tier1_002.md`, … with “part N of M” in the heading.
- Override the automatic choice with `--single` or `--split`; move the cut with
  `--split-threshold N`.

## Index

`artifacts/recon/reports/index.md` is generated by `recon.sh index`. It links
every detailed report (per-host, scans) and links back to `PRIORITY.md`. Do not
hand-edit it; re-run the command after adding a report.

## Naming

- `targets/<target>/PRIORITY.md` — the priority report (or its index)
- `targets/<target>/priority/tier<N>.md` — one tier when split
- `targets/<target>/priority/tier<N>_<NNN>.md` — tier chunk when very large
- `artifacts/recon/reports/hosts/<host>.md` — single-host report
- `artifacts/recon/reports/hosts/<host>-portal.md` — portal checks

## Tone

Write like a recon notebook: observed fact, then why it is interesting, then the
next concrete check. Avoid "may be vulnerable" without evidence; prefer "403 on
`/`, so test whether the restriction is enforced server-side" and record what you
actually sent.

## Linting

```bash
.opencode/skills/recon/scripts/report-lint.sh --target <target>
```

It checks both trees: `PRIORITY.md` plus `priority/`, and the detailed reports
under `artifacts/recon/reports/`. It reports tables, broken relative links,
files missing from their index, and oversized files. A run is not finished while
it exits non-zero.
